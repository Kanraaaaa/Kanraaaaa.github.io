它由什么组成？

可以把 ForgeKernel 想成一套自动化实验室：agent 负责思考和写代码，框架负责安排实验与记录，GPU 负责给出可测量的结果。

🧑‍💻用户：定义任务

描述算子语义、测试输入、参考实现、目标 GPU 和优化目标。

🧭Teacher agent：做规划

分析参考实现和硬件表现，制定 milestone；遇到停滞时诊断并调整计划。

🛠️Student agent：写实现

根据 milestone 逐项修改 kernel 代码。

⚙️ForgeKernel：管流程

启动 agent、提交 GPU 作业、读取判定、保存最佳版本与报告。

🎛️GPU 与分析工具：做验证

实际运行候选 kernel，提供正确性、耗时和可选的 profiling 数据。

📚Skills 与硬件知识库

为 agent 提供操作规范和经硬件探针验证的知识，供后续任务复用。

Teacher 和 Student 是两个逻辑角色，可以配置成不同模型，也可以使用同一个模型。当前主线的 agent 适配代码通过外部 Claude Code CLI 启动 agent；agent 并不是打包在 ForgeKernel 里的模型服务。

一次优化任务怎么跑？

以仓库自带的 RMSNorm 示例为例，用户先描述算子和目标输入，再由 agent 与 GPU 反复协作：

  1. 准备任务
    description.md 描述语义，shapes.json 列出测试形状，task.toml 配置语言、GPU、参考实现、模型与预算。
  2. 创建运行并测参考实现
    ForgeKernel 检查配置、创建独立运行目录，并建立本次比较基线。
  3. Teacher 制定 milestone
    分析任务和参考实现，确定架构方向与分阶段的优化决策。
  4. Student 修改 kernel
    按计划逐步实现，而不是一次性生成整套代码后就结束。
  5. GPU 检查正确性与性能
    运行 judge、测量耗时，并在配置时采集 Nsight Compute 等性能数据。
  6. 按测量结果继续、回退或重规划
    错误改动会回退；正确且有收益的版本保留为当前最佳；持续停滞时 Teacher 重新诊断。
  7. 确认并交付
    保存最佳 kernel 与运行报告。可选地把最佳版本变成下一轮参考，继续自进化。
关键点：agent 提出的代码不自动算成功。是否接受，要看它在目标 GPU 上是否通过正确性检查、是否达到设定的性能目标。

Milestone 和“自进化”是什么？

Milestone 是某个算子的优化课程：描述要做的决策、参数和约束。项目设计的思路是先确定影响最大的结构与编排，再在这个结构内逐步调优。

自进化是把一轮确认通过的最佳 kernel 作为下一轮参考，要求新一轮继续超过它。流程在收益落入测量噪声范围，或没有确认的新最佳版本时停止。

这个停止条件是工程上的搜索判据，不是已经证明找到了数学意义上的全局最优。

ForgeKernel 和 skill 有什么区别？

组成是什么负责什么
ForgeKernelPython 框架与实验流程调度 agent 和 GPU 验证，管理运行状态、结果和报告。
Agent外部 coding agent分析任务、规划优化、编写和修改 kernel。
Skill说明文档与工具脚本指导 agent 如何按项目流程完成工作。
GPU 工具链运行与性能测量环境执行候选代码，产生正确性和性能证据。
更贴切的说法：ForgeKernel 是实验平台；agent 是使用平台设计和实现优化的参与者；skill 是给 agent 的操作手册和辅助工具。

使用前要准备什么？

  • 完整的算子定义：输入输出、数学语义、数据类型与合法输入范围。
  • 代表目标使用场景的 shapes 和测试输入。
  • 可选但通常有帮助的参考实现；ForgeKernel 更擅长在已有实现上继续优化。
  • 运行环境：Linux 或 macOS、Python 3.11+、Git、Claude Code CLI，以及本机或 SSH 可访问的 GPU 环境。
  • 按任务准备对应工具链和预算。仓库快速开始面向 NVIDIA Hopper（H100，sm90）与 Blackwell（B200，sm100），常用 CuTe DSL 或 CUDA C++。

能力与边界

适合的场景

已经有可运行的参考实现，希望针对明确的 GPU、shape 和正确性要求持续优化 kernel。

不保证从零成功

项目说明指出，有参考实现时效果通常更好；从零写出第一版 kernel 并非它最有把握的场景。

结果依赖实验条件

性能数字取决于 workload、参考实现、GPU 和软件版本。仓库公布的提升数据没有在本文中独立复现。

成本不低

完整运行可能需要数小时 GPU 时间和较多模型调用；优化搜索也不等于证明全局最优。

昇腾范围需核实：README 动态栏提到 CANN/昇腾榜单成绩，但快速开始、任务配置和主线代码文档主要描述 NVIDIA、CUDA 与 CuTe DSL。仅凭榜单动态无法确认当前 forge run 已具备通用昇腾后端；若目标是昇腾，应先核实对应代码路径和复现步骤。

最后这样记就够了

人定义任务 → Teacher 规划 → Student 写 kernel → ForgeKernel 组织实验 → GPU 验证结果 → 根据证据进入下一轮。

所以 ForgeKernel 不是一个专门生成 kernel 的模型，而是一个围绕 agent 和 GPU 实测构建的自动化 kernel 优化流程框架。
